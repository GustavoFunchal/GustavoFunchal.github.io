Interactive demo · Collaborative IDS

When should an IDS agent trust its neighbours?

Ten local agents, each running a different ML classifier on an edge device, inspect network traffic. When an agent is unsure (confidence below θ), it asks peers for a second opinion, peer-to-peer. With trust, it only asks peers that have proven reliable, so a weak or compromised neighbour stops spreading wrong answers.

How it works

01

Detect locally

Each local agent classifies its own traffic (normal or attack) with its own model: RF, KNN, Naive Bayes, MLP and others, each with a different accuracy.

02

Ask when unsure

If its confidence is below θ, the agent asks up to three peers directly. Naive picks peers at random; Trust picks the most trusted peers above τ.

03

Aggregate

The agent combines its own answer with the peers' answers, weighted by each classifier's confidence, and makes the final decision.

04

Learn whom to trust

When a peer disagrees, its trust is updated (EMA, β = 0.1): up if it was right, down if it was wrong. The global agent only receives periodic reports.

Try this

  1. Let it run for a few seconds: Naive and Trust both beat Solo, because unsure agents get useful second opinions.
  2. Click Compromise an agent (or click a node). It now answers every help request with the wrong label, confidently.
  3. Switch to Naive: red links appear and accuracy drops, because the bad neighbour keeps being asked. This is negative transfer.
  4. Switch back to Trust: the compromised agent's trust ring shrinks, its column in the matrix fades, and peers stop asking it.
  5. Click Restore all: occasional exploration lets agents rediscover the recovered peer and rebuild trust.
